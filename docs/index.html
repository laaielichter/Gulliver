Test on tiny data before you run on giant data.

Gulliver is an MCP server and CLI that gives AI agents a dress rehearsal for SQL. It estimates the cost, runs the query on 1%, 3% and 10% of the data, predicts the full run, and only lets it run inside your budget.

uvx gulliver-mcp
View on GitHub Set up your agent

Works with Claude Code, Codex, Cursor, Gemini CLI, Claude Desktop, VS Code, Windsurf and any MCP client. Open source, MIT, runs on your machine.

Five steps between your agent and the warehouse

Every answer carries a status and a next_step, so even a small model knows what to do. Limits are set by a human in gulliver.toml; the agent cannot raise them or approve itself.

  1. inspect

    See what is big

    Rows, bytes, partitions and columns, from metadata only. Free.

  2. preflight

    Price it first

    Bytes, rows and money without running, plus scale-lint rules and a read-only gate.

  3. rehearse

    Try it small

    Runs on 1%, 3%, 10% samples and predicts 100% with a range.

  4. run

    Run inside budget

    Per-query and daily limits. Above a threshold a human approves.

  5. receipt

    Show the proof

    Estimated, rehearsed, approved, run: predicted versus actual.

It fixes the SQL, and says what changed

Small models read a lint warning and still write the slow query. gulliver_fix rewrites it for them and labels every change. "Same rows" is only promised when Gulliver has checked the column type on your connection.

  • same exactly the same rows. The default.
  • assumes same rows if the column is a date or timestamp without zone.
  • nulls same rows unless the subquery returns NULL.
  • changes a different result on purpose, like a LIMIT.
-- GV005, ts is TIMESTAMP: same rows
- where date(ts) = '2025-01-20'
+ where ts >= '2025-01-20'
+   and ts <  '2025-01-21'

-- partitions, indexes and Parquet
-- min/max statistics can now skip data

Every "same" rewrite is tested against real data: NULLs, infinity, leap days, the last microsecond of a day, and time zones that repeat midnight.

Add it to your agent

Point it at a warehouse with --dsn, or at a gulliver.toml with connections and budgets. To try it without a warehouse, run gulliver demo.

claude mcp add gulliver -- uvx gulliver-mcp --dsn /abs/path/data.duckdb

# or as a plugin, with the skill included

Also for the pipeline around the query

Sixteen MCP tools in total, each also a CLI command with --json. --toolset core loads only the eight query tools.

gulliver_impactWhat breaks if you change or drop a column: column-level lineage over SQL models or a dbt manifest.
gulliver_driftColumns removed, retyped or added since the last snapshot, and the models they break.
gulliver_diffDo two queries or tables return the same rows? Hashed inside the engine, also across engines.
gulliver_translateSQL between DuckDB, Postgres, BigQuery and Snowflake, with warnings.
gulliver_incrementalCan a full-rebuild model be incremental? The SQL, the dbt config and the rows it saves.
gulliver_checkUnique keys, not null, accepted values, ranges, freshness and row-count jumps in one scan.
gulliver_topThe most expensive repeated queries from query history, with same-rows fixes priced per month.
gulliver_reviewA PR gate for SQL models: new lint, breaking changes, downstream impact and cost per month. Also a GitHub Action.
gulliver lint models/Lint every SQL file in CI: SARIF, GitHub, GitLab and JUnit output, inline ignores, pre-commit hooks.

Questions people ask

Short answers. The README has the details.

Does Gulliver send my data or my SQL anywhere?

No. It runs on your machine and only talks to the databases you configure. Receipts, the spend ledger and approvals are JSON files in ./.gulliver/. There is no telemetry.

Do I need a warehouse to try it?

No. gulliver demo builds a DuckDB database with 5 million events in seconds, and gulliver lint works without any database at all.

Which agents and models does it work with?

Any MCP client: Claude Code, Codex, Cursor, Gemini CLI, Claude Desktop, VS Code, Windsurf. Without MCP, use the CLI with --json, or gulliver tools --format openai (or gemini) for function calling. Every answer is short JSON with a status and a next_step, so smaller models can follow the loop too.

How accurate is the prediction?

It is a growth curve fitted on three samples, so it comes with a confidence level and a range (x0.7 to 1.5 when confidence is high, up to x0.25 to 4 when it is low). On BigQuery the money estimate uses the exact dry-run bytes of the full query. After a real run, the receipt shows predicted versus actual. Joins and skewed data can grow faster than the data; Gulliver flags that instead of hiding it.

Can the agent change or delete data?

Not by default. Only SELECT runs. Writes (CREATE TABLE AS SELECT, INSERT SELECT) need both the call and a human-set allow_write on the connection, and the agent cannot approve its own runs.

How is this different from EXPLAIN or a BigQuery dry run?

Gulliver uses those for the preflight. On top of that it rehearses on samples to show how runtime and output rows grow, rewrites slow SQL with a stated guarantee, enforces a budget, and writes a receipt, in one JSON format across four engines.

Is it ready for production on BigQuery and Snowflake?

Not yet. Both are beta and have been tested against fakes, not live accounts. DuckDB and Postgres are tested in CI, Postgres against a live server. Reports from real warehouses are very welcome.

What comes next

Ideas, not promises. Each one is open for help.

  1. Live tests for BigQuery and Snowflake, so they can leave beta.
  2. A Postgres check for user functions in untrusted languages or with SECURITY DEFINER (GS005).
  3. More same-rows rewrites in gulliver_fix.
  4. Databricks and ClickHouse engines.
